--------------------------------------------------
PROBLEM 1 — INDEPENDENT COLUMN SCROLLING
--------------------------------------------------

CURRENT BEHAVIOR:

The Individual Species Page uses a three-column layout.

The columns represent the major information regions of the Species Page:

- Left column: supporting/species information
- Center column: primary exhibit/reconstruction/content
- Right column: analytical/exhibit information

The problem is that the side columns do not behave independently from the center column.

When the page contains a large amount of content, the user may need to scroll through a large portion or all of the central content before they can conveniently reach content located farther down in the left or right columns.

This makes the page feel like one giant document rather than three coordinated museum information panels.

TARGET BEHAVIOR:

The three-column Species Page should behave as a coordinated three-panel interface.

Conceptually:

┌────────────────┬────────────────────────┬────────────────┐
│                │                        │                │
│  LEFT PANEL    │     CENTER PANEL       │  RIGHT PANEL   │
│                │                        │                │
│      ↕         │          ↕             │       ↕        │
│ independent    │      independent       │   independent  │
│ scrolling      │      scrolling         │   scrolling    │
│                │                        │                │
└────────────────┴────────────────────────┴────────────────┘

Each column should be capable of reaching its own content without depending on the scroll position of the other columns.

However, this must NOT create an ugly interface filled with unnecessary nested scrollbars.

The scrolling behavior should feel intentional and museum-like.

--------------------------------------------------

Before modifying anything:

1. Inspect the existing Individual Species Page component.
2. Identify the parent layout that creates the three columns.

The desired behavior is:

- The layout should not produce multiple stacked scrollbars inside the same panel unless genuinely required by the component.

PROBLEM 2 — TEXT WRAPPING
--------------------------------------------------

CURRENT BEHAVIOR:

Some text within the Individual Species Page does not wrap correctly.

This can cause:

- text to extend outside its intended container
- long words or labels to push columns wider
- text to overlap adjacent elements
- cards to expand unexpectedly
- horizontal overflow
- awkward single-line text
- clipped text
- content becoming unreadable
- layout instability when longer species names or scientific terminology are used.

This is particularly important for Dinopedia because scientific names, taxonomy, anatomical terminology, measurements, and scientific descriptions can naturally contain long strings.

TARGET BEHAVIOR:

Every piece of textual content should remain inside its intended visual container.

Text should wrap naturally according to the available width.

For example:

A long scientific name should remain inside its card rather than forcing the card or column to expand.

A long description should wrap onto additional lines rather than overflowing.

A long label should remain readable rather than being clipped.

No text should force the three-column layout to change width unexpectedly.

--------------------------------------------------
TEXT WRAPPING IMPLEMENTATION
--------------------------------------------------

Before modifying anything:

1. Inspect the Species Page for existing text containers.
2. Identify reusable typography components.
3. Identify flex/grid children containing text.
4. Look for missing min-width: 0 behavior in flex/grid children.
5. Look for fixed-width elements that prevent wrapping.
6. Look for nowrap rules.
7. Look for overflow rules that clip text.
8. Look for long unbroken strings such as:
   - scientific names
   - taxonomy
   - measurements
   - anatomical terms
   - labels
   - exhibit metadata.
9. Determine whether the problem is caused by the parent container, the text element, or both.

Do NOT simply apply:

overflow-wrap: break-word;

to everything.

That may hide the underlying structural problem.

Instead, use appropriate combinations of:

- width constraints
- max-width
- min-width: 0
- flex behavior
- grid behavior
- normal white-space behavior
- overflow-wrap
- word-break only where genuinely necessary
- appropriate text container sizing.

Preserve normal word boundaries whenever possible.

Do NOT aggressively break normal words unless a genuinely unbreakable string requires it.

--------------------------------------------------
TEXT MUST NOT BECOME SMALLER
--------------------------------------------------

IMPORTANT:

Do NOT reduce font size to solve text wrapping.

Do NOT reduce padding excessively.

Do NOT compress the interface simply to force everything onto one line.

Readability is more important than fitting everything on one line.

If text needs two or three lines, allow it to use two or three lines.

The goal is:

READABLE + STABLE

not:

SMALL + FORCED INTO ONE LINE.

HORIZONTAL OVERFLOW
--------------------------------------------------

After implementing the fix:

Check the entire Species Page for unintended horizontal overflow.

The following should NOT happen:

- the browser gains a horizontal scrollbar because of a text element
- one long word expands a column
- a card becomes wider than its parent
- text escapes outside a card
- a button pushes another element outside its container
- the central column expands because of content from a side column.

Do not solve horizontal overflow by blindly applying:

overflow-x: hidden;

to the entire page.

That can hide real layout problems.

Find and fix the element responsible for the overflow.
