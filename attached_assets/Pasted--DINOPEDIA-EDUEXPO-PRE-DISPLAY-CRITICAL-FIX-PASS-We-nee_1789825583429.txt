We need to make a focused, careful bug-fixing pass on the existing Dinopedia application.

Dinopedia is a digital museum / encyclopedia for prehistoric life, currently focused primarily on dinosaurs.

The current production UI and visual identity are already established.

Fix these carefully and verify that the fixes do not introduce new responsive or layout problems.

# 1. SEARCH DROPDOWN OVERLAPPING / LAYERING BUG

## Problem

The search functionality currently has a visual layering problem.

When the user types into the search field and the search suggestions / results dropdown appears, the dropdown does not properly sit above the surrounding interface.

Some surrounding elements visually overlap it or appear in front of it.

The dropdown must behave like a proper overlay.

## Desired behavior

When the search dropdown opens:

* it must appear above surrounding content
* it must not be clipped by an unrelated parent container
* it must not disappear behind cards, sections, headers, or other UI
* it must remain visually attached to the search field
* it must remain correctly positioned when the page is scrolled
* it must work at desktop and mobile widths
* it must not cause the surrounding layout to shift unexpectedly
* it must close appropriately when search interaction ends, according to the existing application behavior

## IMPORTANT

Do NOT simply increase z-index randomly.

First inspect the DOM hierarchy and identify:

* stacking contexts
* positioned ancestors
* overflow properties
* clipping containers
* z-index relationships
* transforms that may create stacking contexts
* sticky/fixed elements
* parent containers using overflow-hidden / overflow-auto

If the dropdown is being clipped by an ancestor, fix the actual structural cause rather than endlessly increasing z-index.

The final implementation should use a sensible stacking hierarchy.

The dropdown should visually sit above the content without causing unrelated elements to gain excessive z-index values.

## Responsive requirement

Check:

* normal desktop width
* narrower desktop width
* tablet width
* mobile width

The search dropdown must remain usable and correctly positioned at all of these sizes.

# 2. CRITICAL COLUMN SCROLLING BUG / REGRESSION

This is the most important issue to handle carefully because a previous attempt to fix scrolling caused a regression.

## Existing behavior / history

Dinopedia uses a multi-column museum-style layout.

The application has areas where the center/main content and side sections have their own intended scrolling behavior.

Previously there were problems where:

* side sections would not scroll independently
* scrolling one area affected another area
* the center section did not behave correctly

A previous attempted fix made the situation worse:

**The center column now stops scrolling before reaching the actual bottom of its content.**

In other words, the user can scroll down the center content, but the center scroll area ends prematurely and some content below it becomes inaccessible.

This must be investigated rather than patched blindly.

## FIRST STEP — INSPECT THE EXISTING IMPLEMENTATION

Before changing anything:

Identify exactly how scrolling currently works.

Inspect:

* body/html height
* page-level overflow
* main application container height
* grid/flex containers
* center column height
* left column height
* right column height
* overflow-y values
* min-height
* max-height
* height: 100vh / 100dvh / etc.
* nested scroll containers
* sticky elements
* position: sticky/fixed
* flex children with min-height: 0
* grid row sizing
* scrollbar containers
* mobile media queries
* desktop media queries

Determine which element is actually responsible for scrolling in each column.

DO NOT immediately rewrite the layout.

---

## DESKTOP SCROLLING GOAL

At normal desktop zoom and normal desktop viewport sizes:

The museum's three-column layout should behave naturally.

The center content must be able to scroll **all the way to the actual bottom of its content**.

No content should become inaccessible because a parent container has an incorrectly constrained height.

If the side columns are intended to scroll independently, they should do so.

If a side column's content is shorter than the center content, it should not create strange empty scrolling behavior.

Do not force every column to have identical content height.

---

## IMPORTANT: DO NOT BREAK THE EXISTING THREE-COLUMN LAYOUT

The three-column museum layout is intentional.

Do NOT:

* remove the columns
* redesign the page
* collapse everything into one column on desktop
* introduce arbitrary fixed heights
* introduce giant blank spaces
* make the center column artificially short
* make the side columns consume the entire page unnecessarily

The objective is correct scrolling, not a new layout.

---

# MOBILE SCROLLING

The mobile version should not inherit desktop nested-scroll behavior in a way that makes the page difficult to use.

Inspect the mobile CSS carefully.

On mobile:

* the page should scroll naturally
* content must remain reachable
* no section should be trapped inside an unnecessarily short scroll container
* no content should be cut off
* nested scrolling should only exist where it is genuinely necessary

Do not sacrifice mobile usability in order to fix desktop scrolling.
