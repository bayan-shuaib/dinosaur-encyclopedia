# 1. CORE REQUIREMENT

Dinopedia species pages currently have two major experiences:

1. **Life Appearance & Behavior**
2. **Anatomy & Scientific Evidence**

We are now adding a **THIRD FULL SPECIES MODE**:

# 3. EVIDENCE & RESEARCH

This is NOT a subsection inside the existing Anatomy & Scientific Evidence mode.

This is NOT a collapsible "How Do We Know?" panel.

This is NOT a small addition to the existing Scientific mode.

It must be implemented as a **full independent species-page mode**, at the same level as the existing modes.

The species-page navigation should conceptually become:

```text
LIFE
Life Appearance & Behavior

ANATOMY
Anatomy & Scientific Evidence

EVIDENCE
Evidence & Research
```

The user should be able to switch between these experiences just as they currently switch between the existing species modes.

---

# 2. PURPOSE OF THE NEW MODE

The new Evidence & Research mode should answer a fundamentally different question:

> "What evidence supports what we know about this dinosaur, how was that evidence interpreted, how confident are scientists, and what remains uncertain?"

The existing Life mode answers:

> "What was this animal probably like when alive?"

The existing Anatomy mode answers:

> "What was this animal physically built like?"

The new Evidence & Research mode answers:

> "How do we know what we think we know?"

These three experiences must remain conceptually distinct.

# 3. EVERY DINOSAUR MUST HAVE AN EVIDENCE PROFILE

This is a major architectural requirement.

The system should be designed around the assumption that:

> EVERY dinosaur species in Dinopedia has a Scientific Evidence Profile.

Do NOT make the entire feature optional in the data architecture.

Do NOT design this as:

```ts
scientificProfile?: ScientificProfile
```

where most species simply have no profile.

Instead, make the evidence profile a required part of the species data architecture, either directly:

```ts
scientificProfile: ScientificProfile
```

or through a required profile reference:

```ts
scientificProfileId: string
```

with a corresponding profile registry.

Every existing dinosaur in the database must have a valid profile entry.

However:

**Do not fabricate scientific information just to populate profiles.**

If a dinosaur has limited evidence, its profile should explicitly communicate:

* Limited evidence
* Unknown
* Insufficient fossil material
* No direct evidence
* Hypothesis
* Unresolved

etc.

A species having limited evidence is scientifically valid.
